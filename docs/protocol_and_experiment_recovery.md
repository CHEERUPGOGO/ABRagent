# Writer协议与实验局部失败恢复

## Writer

新设计使用统一的 `version=2` JSON示例。Writer允许数值、null，以及材料或工艺文字声明；明确文字可省略 `quantity_kind=text`，数值字符串仍不能伪装成文字。新声明可标记 `engineering_proposal` 或 `user_requirement`，后者保留来源但不会自动取得锁定或审核权限。同字段、同值、同单位的重复声明沿用已有来源和锁定，不因冗余输出拒绝整稿。参数命名空间、分数单位和计量分母要求在生成前说明。

v2接收时忽略Writer自行返回的布尔`locked`，将原声明、规范前哈希和字段位置留在`raw_response`及`ignored_writer_lock_claims`。它没有权限效力，不能授予新锁定或解除既有锁定；已有字段仍由原方案表的值、单位、身份和锁定校验。非布尔`locked`和其他权限元数据继续拒绝。该兼容只去掉模型无权设置的标记，不改变科学正文、数值或来源，不重发已经完成的Writer请求，不退还已用协议预算。

`util/writer_protocol.py`先处理确定且不改变内容的协议书写：去掉外层JSON围栏，子节ID统一小写（碰撞时拒绝），同步章节引用，并把已明确无量纲字段的`1`/`fraction`单位归一为空串。通用 `quantity_kind=fraction` 按 `ratio` 处理，不猜测质量、体积或位点分母。已知同尺度单位规范为字段要求的书写，例如`μm/µm→um`、`m²/s→m2/s`、`μL→uL`，不执行`mm→um`这类需要换值的转换。正文、数值和来源保持不变。旧检查点补丁兼容由原响应精确重算的规范前哈希，不重置协议计数。

用途标签兼容：误填到`quantity_kind`的`target/lower_bound/upper_bound/experiment_max`移入`quantity_role`，已有不同用途则拒绝。量值类型只按原声明的文字、分母或单位记录为`text/ratio/physical/other`，不把通用比例猜成位点或质量分数，不丢失上下限用途。原值、分母和原始响应不变。

空倍率单位仅受控补全：参数身份须明确为`condition.c_rate`（含既有别名或显式canonical_path），值须是有限正数，原`meaning`须明确倍率/C-rate且没有电流、容量、温度、否定或待确认等冲突。仅未锁定新声明的空串/null/省略单位可补为`C`，不推断倍率值或参考电流；显式`mA/g`、`℃`、`1`等单位不更改。确定性规范与协议补丁共用同一条件，既有方案表的锁定值及缺项仍不覆盖。历史失败响应可在原预算内只读重验，不自动发布或授予科学审核通过。

仍有错误时按 `runtime_options.stage4_repair.protocol_rounds` 调用 `writer_protocol_repair`，独立于同节的 `content_rounds` 正文修复和 `review_rounds` 学术审核预算。每轮提交当前文档与剩余错误；补丁JSON或字段格式错误可继续下一轮，合法部分逐轮保留，不从原稿反复重做。匹配基准哈希后，可提交参数路径/元数据补丁及受限正文引用补丁；参数路径兼容点分字符串及 `["parameters", "cathode.porosity"]` / `["cathode", "porosity"]` 数组。非法量值标签可修正为已知类型，已明确的计量口径保持不变。未登记命名空间可按明确映射 `doping.*→cathode.doping.*`、`synthesis.*→process.*`、`test.*→condition.*` 修正，原后缀不变；已有合法字段不能改绑。不得修改值、科学正文、来源、组别、条件、锁定，不删除记录。比例口径有歧义或正文结构缺失时不能为通过而放行。

### 参数协议扩展权限：先建议、后签发

`writer_protocol_advice.py`补齐原元数据白名单无法处理的错误。程序只为本轮报错的新字段生成有限候选，再调用只读模型`writer_protocol_advice`，要求逐项给出修改前后建议、原因与包含该字段引用的精确正文原句。建议缺项、重复、越权或不能定位时不发起补丁。普通元数据修复继续沿用原接口，不增加建议调用。

新增转换覆盖四类：明确百分比在同一显式分母下转换为0–1分数；完整、有限且非编号/范围的数值字符串恢复为JSON数值；有已归档文献来源、且当前正文明确采用为待验证方案的取值，从`literature`改为`engineering_proposal`；误占规范数值字段的专属声明迁移到独立路径。原来源、工况、样品、分母、候选角色均保持。已有方案字段及其别名、锁定null和模型来源不获得此权限；原文献样品/工况/性能不能直接晋升主方案。

作用域迁移权限v2（`scope_relocation`）只针对本轮报错、正文已引用、且未在方案表登记的新声明。例如`cathode.L_um`带`conditions="干涂层"`时，程序生成同组件的稳定独立路径`cathode.scoped_<工况哈希>.L_um`，补`canonical_path="cathode.L_um"`，原value、unit、basis、source、conditions、scope、group_id、purpose和分母保持。只允许原规范身份，拒绝路径碰撞、跨组件改绑、已有字段或锁定别名绕过，迁移前仍验原字段的类型、单位与范围；主工况无条件字段不需要迁移。新`user_requirement`可保留其依据迁移，但不取得锁定或科学审核权限。

模型仍只选择程序签发的correction编号，不能自由提交new_path或删改条件。程序同步正文`param`、字段级`derived:calculated.*`引用及`ratio_inputs`依赖，不替换普通文字、标题或来源。签发路径和完整原声明在应用时再次核对，迁移前后数量身份须一致；原字段和目标字段均禁止叠加任意元数据补丁。独立复核须确认原样品/工况及正文归属不变，迁移不会把专属工况视为主方案，也不保证后续几何、数值计算或科学审核通过。

模型只能通过`corrections`选择程序签发的编号，不能自填value、basis或source；同一字段不能同时叠加元数据补丁。提交后由独立只读调用`writer_protocol_verify`核对实际采用及等值含义，有歧义或科学身份变化则拒绝。该复核不代表完整科学审核通过，后续Reviewer仍必需。

每轮新增权限最多包含一次建议、一次补丁及一次参数复核，全部计入原`runtime_options.stage4_repair.protocol_rounds`轮次，YAML是预算唯一来源；本轮三类请求分别调用前占用，响应、签发范围和拒绝原因保存在`repair_history.parameter_advice/parameter_review`等记录中。中断不重发，恢复只复用已存响应。每轮按`authority_version`重放原权限；v1旧轮次不补发v2建议。旧版本因缺权限返回的空补丁，可在显式恢复时沿用剩余次数新开v2轮次；已用次数不重置，预算耗尽仍拒绝。v2无修改补丁仍停止，语义否决或中断不因升级自动重试。现有已发布报告不自动改写。

### 正文引用修复与错误全集

`numeric_bindings.source_parameters`一次收集所有未采用的新声明；`writer_references.collect_errors`同时列出参数协议错误、未知/非法正文引用及未绑定字段，给出具体JSON路径。最终失败清单保存于检查点并随Writer错误传到诊断报告，不能只显示首个字段。

协议补丁可选`references`数组，每项为`{field, body_path, quote, value_quote}`。只针对未绑定的新声明，由程序将指定`sections/.../body`里唯一上下文中的完整量值或文字替换为`{{param:field}}`。补丁没有任意replacement权限；标题、参数、文献引用、代码、公式和已有模板标记不能改。原值、单位、分母、样品、条件、用途和来源不变；仅允许已登记单位换算和原声明/正文明确支持的百分比口径，不从化学式系数猜比例。文字逐字不等价时标记`equivalence_mode=semantic_text`，只能作为待复核绑定；独立审核须确认完整正文支持原值全部含义。例如“A位为Li位；A位引入Na+”可支持“Na占Li位（A位）”，只提Na、未声明占位则不能支持。否定、候选范围、价态与条件变化不放宽，不能从参数说明或常识补原文缺失关系。

数值等价不等于语义归属正确。程序校验后单独调用一次`writer_reference_verify`，逐项核对主组/候选/对照、文献原值、工况、目标/上限及比例分母。每项须返回匹配输入哈希的明确支持与理由；缺项、重复、否决或中断均不合并。该复核只审核引用归属，不能代替随后Reviewer的科学审核。

补丁与独立复核各在调用前持久化占用机会，保存完整原始响应及前后哈希。各轮补丁和引用复核存入 `repair_history`；恢复先按顺序重验已存响应，仍有协议错误时使用 `runtime_options.stage4_repair.protocol_rounds` 中的剩余机会，不重复生成全文或重发已有调用。预算可在YAML中增减，历史计数不重置。前一轮已绑定的分母可展开供后续引用等价检查使用。无修改的补丁、引用语义否决或复核中断停止本轮恢复，不反复要求模型改判。剩余未绑定字段仍明确列出，不补造缺失内容；本功能不会自动重跑已发布报告。

完整原始响应和协议状态保存在 `stage4_repair_checkpoint.json` 的 `writer_protocol`，并保留完整Writer输入及当前参数基准。首次调用、各轮协议修复调用前持久化尝试标记；返回后保存原始输出，成功补丁保留。重启复用已保存响应，不重新生成全文或重发中断调用。参数基准改变时拒绝旧响应。空稿也保存检查点；协议失败不触发几何生成或参数维护，诊断交付不再被描述为“规则审查通过”。

接口误报 `finish_reason=stop` 但JSON在字符串/容器内结束时，复用既有“完整输出至多两次”的剩余机会：仅确认首次传输且尚未进入协议修复时，持久化占用一次 `writer_completion_retry`，扩大预算并要求精简完整输出。原响应、重试响应分别归档，后者重新通过全部协议和科研审核；传输已经重试、调用中断或完整但非法的协议不能再次全文生成。空稿失败不再以待补检索阻断诊断交付，原检索预算与诊断保留。

已发布旧报告不会因升级代码自动改变配方或重跑模型。原始输出无法合法恢复时，检查点明确保留错误，不能提升为已审核方案。

单字符语法恢复仅处理解析器报错位置的内部闭括号缺失：字符串之外、栈顶与父级要求唯一确定的`]`/`}`，补入后须通过完整JSON及五节结构校验。禁止补截断尾部、重复键、字符串或逗号猜修；原始响应保留，插入位置与前后哈希存`syntax_repair`。不消耗模型修复次数，也不跳过后续字段和科研审核。

数值渲染器与方案表共用面容量公式：总面载量 × 活性质量占比 × 明确比容量 / 1000（mAh/cm²）。比容量缺失、单位不符或工况不一致保持未完成；不能从1 C电流定义补容量，工程假设仍保持原依据级别。

重建课题重新登记用户条件时，完整文字配方如 `1 mol/L LiPF₆/EC+DMC` 的独立 `unit` 可能为空。仅在同字段、同值且文字内明确包含既有锁定单位时沿用该单位，并同步后续要求契约；既有方案行保持不变。显式不同单位、不同配方、原文不含单位或数值字段缺单位仍拒绝，不解除用户锁定。

## Stage 4连续失败审查

默认v2正文修复中，同一问题连续两轮未修复时，`repair_diagnosis.py`调用一次独立的`repair_case_review`。问题按原句、类型、原因及关联字段识别，不依赖每轮重新分配的`issue-0`序号；中间已经解决的问题不累计为连续失败。

审查输入包括当前相关段落、参数和数值计算路径、前两轮具体补丁、事务拒绝原因及证据。模型先判断问题是否成立，再区分科学/证据缺口、程序公式不足、接口格式限制和措辞误判，不能只是重复原建议。行动分为：

- `repair`：把诊断及下一步交给剩余的第三轮正文修复，保持原授权范围。
- `recheck`：在六轮科学审核总预算内重新交Reviewer核验原问题；诊断本身不能消除问题或授予APPROVED。
- `defer`：缺证据或当前接口无法处理时停止对该问题的无效补丁尝试，原问题仍在审核和报告中保留。

审查不消耗正文补丁次数，每个连续失败问题只调用一次；调用前保存占用记录，完整响应保存在`repair_diagnoses`并进入RAG及设计档案。中断或非法响应保留失败记录，不自动重发；参数、引用、锁定和科研审核仍由原合并器执行。只有字段包装不同的参数补丁，兼容`{path,field:{...}}`和`{path,value,unit,...}`两种写法。引用中的文字可与同次已授权参数修改后的显示值一致，不因模型提前刷新了正确显示值而拒绝；未授权变值仍拒绝。

## 实验校验与局部保留

未锁定的null表示尚未确定，不能作为数值冲突基准。Stage 5B可以对缺失的加工/测试参数提出工程建议，但不能用它代替缺失的主材料组成或回填PINN物性。锁定null、真实数值（含0）、真实单位冲突继续受保护。`ref`必须指向非空已定参数。

材料化学式等无单位对照字段的 `unit=null` 与空串等价，不再因此撤下有效组别；有量纲数值仍按原规范单位核验，不替换对照值。

`experiment_repair.py`在规范化和诊断前即归档原稿，模型补丁及最终错误也保存。无法修复的参数从活动参数表移入 `pending_parameters`，只暂停引用该参数的段落和目标测试；原步骤保存在 `pending_sections`/`pending_tests`，其他有效段落、参数、分组继续保留。禁止把“待确定”字符串塞入物理数值字段，导致终验再次失败。全部待定内容和原稿都可回溯。

## 状态表达

Stage 5执行器和门禁共用 `experiment_design.delivery_status()`：

| 状态 | 含义 |
|---|---|
| PASSED | 生成的实验推荐通过校验，未登记局部待定或目标缺口 |
| CONDITIONAL | 保留具体方案，但存在局部待定、未登记对照或测试缺口 |
| FALLBACK | 采用engineering_fallback工程模板，详细实验生成未成功 |

模板即使`pending_fields=[]`也不能写成PASSED。报告优先模式仍允许附条件交付；Stage 5的物理结果和实验结果分别披露，物理不适用不能掩盖实验回退。报告渲染v30在实验章节显示交付状态及原因。
