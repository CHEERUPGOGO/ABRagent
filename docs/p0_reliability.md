# P0：局部恢复与实验一致性

本次改进保持既有模型调用预算与六阶段结构，优先解决“一个失败条目导致整份结果降级”和“未知要求被免除验证”的问题。

## 需求保留与验证责任

`verification_needed`采用三态：`true`需要验证，`false`明确无需验证，`null`尚不能判断。解析失败及原文漏项保留为未知，Stage 5B仍须给出对应测试安排或明确的获取路径，不能直接标为不适用。历史`unparsed`任务中错误的`false`只读解释为未知。

`requirement_recovery.py`逐项验收并保留有效材料约束、原文定位、任务类型与关联。一次局部修复只允许更改失败条目；修复服务失败也不清空通过项。未覆盖的原文片段进入待解析清单，不补造阈值或实验条件。部分解析任务同样通过已验证声明建立主方案，不能回到正文关键词猜测材料与添加剂。

## 研究记录独立验收

`research_records.py`分别校验回答、候选、论证及选中关系，复用原有原句、引用、参数绑定规则。有效记录保持不变，失败记录保存到`record_errors`并在原来的维护重试中定向修复；中断时已通过内容仍保留。最终审查只撤下无效记录并补对应缺口，不整份清空。

该机制不放宽证据标准：未知引用、原文中不存在的结论和陈旧参数仍拒绝。已丢失的历史结构化内容不会被凭空恢复，须在后续运行中重新从已有正文提取。报告保留未解决诊断，不能以局部恢复宣称研究已完成验证。

## 实验前一致性与局部待定

`experiment_consistency.py`在Stage 5B调用前核对方案表、固定声明、参数别名与已指出的字段冲突，形成`consistency`快照和`pending_operations`。几何修订仍由既有事务与同步契约负责。冲突字段及相关配料/装配保持待定，其他有效参数、段落、组别和测试安排继续保留。

主方案材料、组成和电解液只允许引用，不得通过实验命名空间新增。对照参数必须对应已登记的`group_id`、`canonical_path`和组内变化，不能混入主组。重复赋值、错误参数引用与失效对照进入既有局部修复；一个坏对照或一个遗漏目标不会令整张组表/测试表回退。

未提到某添加剂不代表禁止它；审核中的相关争议仅标为待核对，程序不代替用户决定配方。已有配方争议也不会因为报告排版完成而消失。

存在待定字段、失效分组或测试缺口时，实验状态为`CONDITIONAL`。报告优先模式仍可交付如实披露的候选报告；严格门禁不将该状态视为可执行实验。检查器重算一致性快照，不能通过删除待定标记继续使用旧方案。

## 验证与生效

新增离线回归覆盖混合成功/失败需求、重试锁定、未知验证责任、研究记录部分成功、服务中断、主对照参数范围、条件性阶段状态及实际RAG写作接线。运行`python -X utf8 -m pytest -m "unit or not external"`，不默认调用外部服务。

新实验生成指纹升级，重新运行相关阶段时应用新规则；不会为升级自动重跑已归档研究。报告渲染版本为15，仍使用原有确定性生成和终审。
