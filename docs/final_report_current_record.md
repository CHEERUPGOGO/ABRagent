# 最终研报使用统一当前记录

最终报告以`report_record.json`作为一次生成的完整输入记录。它来自当前被选定且校验一致的方案版本，不依据文件修改时间选择“最新科学结论”。

## 记录与章节

- 方案表是值、单位、用途及锁定状态的权威来源。
- 第二部分使用当前有有效审核绑定的论证；第三部分投影同一方案表。
- 第五部分只读取快照内当前实验计划；Stage 5执行状态须对应相同计划哈希。
- 摘要读完整当前字段，不因组成解析字符串省略比例而误称比例未声明。
- 附录的当前覆盖指向本版第二、三、五部分，并由同一实验记录给出分组。原Stage 4逐项回答及历史审核保存在快照来源档案中，不能把当时提议的措施显示为当前已经安排。
- 当前相容性违规、研究缺口和科学保留状态仍展示；归档不是科学批准，也不意味着历史科学疑问已经解决。

## 取样、发布与校验

生成前在课题锁下取样，验证设计与方案表、实验与执行状态、选定仿真的版本关系。生成结束与发布后再次比较输入哈希，变化时保留旧报告或回滚；主报告、独立补充材料与快照必须一起发布。实验渲染缓存不是权威输入。

渲染v45将`final_research_report.md`止于第6节参考文献，阶段履历、完整覆盖、审核及参数档案写入`final_research_report_supplement.md`。正文不添加“见附录/补充材料”提示句。补充材料保留完整科学保留意见，正文仍保留交付状态及实际科学边界；分文件不提升科学审核。两份文件的隐藏bundle、identity及record标记必须一致，缺失、跨版本或被篡改的审核块会使终审失败。Stage 6完成后的履历刷新只更新补充材料，主报告仅刷新原有审计状态。

最终检查器核对快照内容指纹、当前输入、相同投影以及所有报告块。改变方案或实验后只重写某个章节不能通过验收。Stage 6自身完成日志不参与科学输入哈希，前五阶段履历仍纳入。

等价单位、同义表达和科学缺口可保留。明确否定反转、未知条件写成确定条件、用户比较关系或显著性丢失属于一致性问题。新实验引用用户目标数值时带`requirement_id`，判定正文保留该目标限定。

旧报告仍可按原单文件契约读取；再次正式生成时使用分文件契约。任何在副本生成并发布报告的维护流程，都必须同时发布主报告、补充材料及`report_record.json`。
