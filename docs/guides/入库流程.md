# LMLLM 锂电池文献入库全流程

> 从 PDF 论文到 RAG 问答 —— 完整操作手册

---

## 流程总览

```
PDF 论文（原始命名）
  │
  ▼  [0] 提取 DOI，按 DOI 重命名 PDF   (doi.py / extract_doi_only.py)
  ▼  [1] PDF → Markdown 转换          (MinerU API)
  ▼  [2] 主文献 + SI 合并             (merge_markdown)
  ▼  [3] 文本清洗                     (cleaner_v2_standalone)
  ▼  [4] 电池类型分类                 (battery_type_agent)
  ▼  [5] 组件分类 (正极/负极/电解质)   (component_type_agent)
  ▼  [6] 元数据提取                   (extract_meta)
  ▼  [7] 段落标签标注 + Chroma 入库    (v5_qwen pipeline)
  ▼
RAG 检索问答                         (src/lmllm/RAG)
```

## 步骤 0：从 PDF 提取 DOI，按 DOI 重命名

**作用**：原始 PDF 文件名不一定包含 DOI，需要从 PDF 正文中提取 DOI 并重命名，方便后续流程以 DOI 为唯一标识。

三个脚本**选一执行**，推荐使用 `extract_doi_dedup.py`（自带文件名去重）：

### 脚本一（推荐）：`extract_doi_dedup.py`（带 DOI 去重 + 命令行参数）

自动处理文件名重复：当 `pdf_doi/` 中已有同 DOI 文件时跳过，也可选择保留较大文件。

```bash
# 默认配置（输入 papers/pdf/242 → 输出 papers/pdf_doi）
python extract_doi_dedup.py

# 指定输入/输出目录
python extract_doi_dedup.py --input papers/pdf/chan --output papers/pdf_doi

# 重复时保留较大的文件（覆盖已存在的较小文件）
python extract_doi_dedup.py --keep-larger

# 预览模式（不实际复制）
python extract_doi_dedup.py --dry-run
```

| 参数 | 说明 |
|---|---|
| `--input` | 原始 PDF 目录（默认 `papers/pdf/242`） |
| `--output` | 成功输出目录（默认 `papers/pdf_doi`） |
| `--no-doi` | 提取失败输出目录（默认 `papers/pdf_no_doi`） |
| `--keep-larger` | 重复时比较大小，保留较大的文件 |
| `--dry-run` | 仅预览，不实际复制 |

### 脚本二：`doi.py`（带 merged 去重检查）

从 PDF 正文提取 DOI，并检查 `papers/merged/` 中是否已存在该 DOI 的合并文件：
- 成功提取 DOI → 重命名为 `{doi}.pdf` 复制到 `pdf_doi/`
- 提取失败 → 用 md5(原文件) 命名，复制到 `pdf_no_doi/`

```bash
python doi.py
```

**配置**（在脚本顶部修改）：
```python
INPUT_DIR = "/home/ls/xiaoyue/LLM2/LMLLM/papers/pdf/chan"     # 原始 PDF 目录
OUTPUT_OK = "/home/ls/xiaoyue/LLM2/LMLLM/papers/pdf_doi"      # 提取成功输出
OUTPUT_FAIL = "/home/ls/xiaoyue/LLM2/LMLLM/papers/pdf_no_doi" # 失败输出
MERGED_DIR = "/home/ls/xiaoyue/LLM2/LMLLM/papers/merged"      # 用于去重检查
```

### 脚本三：`extract_doi_only.py`（纯提取，命令行参数控制）

支持命令行参数，可灵活指定输入子文件夹和输出目录，并保留子文件夹结构。

```bash
# 默认：扫描 papers/pdf/ 下所有子文件夹
python extract_doi_only.py

# 依次处理单个子文件夹（输出自动带子文件夹名）
python extract_doi_only.py --input papers/pdf/242   #运行这个改一下子文件夹名称
python extract_doi_only.py --input papers/pdf/chan

# 无 DOI 的文件原地跳过，手动处理（默认复制到 pdf_no_doi/）看不到哪个文件没处理在文件夹中不好找
python extract_doi_only.py --input papers/pdf/242 --skip-no-doi

# 自定义输出目录
python extract_doi_only.py --input papers/pdf/242 --output /tmp/test_doi
```

| 参数 | 说明 |
|---|---|
| `--input` | PDF 源目录（默认 `papers/pdf`） |
| `--output` | 成功输出目录（默认 `papers/pdf_doi`） |
| `--no-doi` | 失败输出目录（默认 `papers/pdf_no_doi`） |
| `--skip-no-doi` | 无 DOI 的文件原地跳过，日志标记为「待手动处理」 |

**输出结构**（自动保留子文件夹名）：
```
pdf_doi/242/10.1002_adma.202107326/paper.pdf    ← 来自 papers/pdf/242/
pdf_no_doi/242/unknown.pdf                       ← 无 DOI 默认复制
```

**提取规则**（三个脚本通用）：
- 扫描 PDF 前 5 页 + 最后 3 页
- 正则匹配 `10.xxxx/xxx` 格式的 DOI
- 成功 → 文件名中的 `/` 替换为 `_`，复制到 `pdf_doi/`
- 失败 → 复制到 `pdf_no_doi/`

## 步骤 1：PDF → Markdown 转换（MinerU API）

**作用**：将按 DOI 重命名后的 PDF 论文通过 MinerU 精准解析 API 转为 Markdown，保留公式、表格、图片。

```bash
cd /home/ls/xiaoyue/LLM2/LMLLM

# 使用 preprocessing/config.yaml 中的配置
python preprocessing/pdf_to_markdown.py

# 或指定 PDF 目录和输出目录
python preprocessing/pdf_to_markdown.py \
  --pdf-root ./papers/pdf/242 \
  --output-root ./papers/markdown/242

# 查看转换结果
ls papers/markdown/242/10.1002_adma.202107326/
# → 10.1002_adma.202107326.md  + images/ 目录
```

**关键配置**（`preprocessing/config.yaml`）：
```yaml
mineru:
  token: "your-mineru-token"      # MinerU API 令牌
  model_version: "vlm"           # vlm 模式 GPU 加速
  enable_formula: true           # 保留公式
  enable_table: true             # 保留表格
paths:
  pdf_root: "/path/to/papers/pdf_doi"
  output_root: "/path/to/papers/markdown"
processing:
  batch_size: 50                 # 每批 50 个 PDF
  max_retries: 5                 # 失败重试 5 次
```

## 步骤 2：合并主文献 + 补充信息（SI）

**作用**：每篇 PDF 可能生成多个 md 文件（主文献 + 补充材料），合并为一个完整文件。

```bash
python preprocessing/merge_markdown.py \
  --input ./papers/markdown/242 \
  --output ./papers/merged/242
```

**合并规则**：
- 主文献 .md 在前，SI（含 `_si_` / `supplement` 等关键词）在后
- 输出文件名 = 子文件夹名（即 DOI）.md
- images/ 目录原样复制

## 步骤 3.1：中文文献入库说明（2026-08-20 起支持）

清洗器 `cleaner_v2_standalone.py` 与 v5 管线的切分逻辑已升级为**中英双语规则并联**：

- **英文文献**：清洗/切分行为与之前完全一致（中文规则不会匹配英文文本，已做全量回归验证）
- **中文文献 / 中英双语文献**（如 Springer 中文期刊）：自动应用中文规则 —— 过滤中文噪音（收稿日期/基金项目/作者简介/中图分类号/文章编号等）、中文图注（图1/表 2/图S1）、中文章节标题（2.1 电解液）、中文参考文献（"[1] 张三…"）、中文摘要/关键词；段落切分按中文句末标点（。！？）正确分段

中文文献与英文文献走同一条入库链路，无特殊操作：

```bash
# 1. 中文 PDF（如 papers/pdf/中文/ 下的知网文献）→ MinerU 转换
python preprocessing/pdf_to_markdown.py --pdf-root ./papers/pdf/中文 --output-root ./papers/markdown/中文

# 2. 主文献 + SI 合并（可选）
python preprocessing/merge_markdown.py --input ./papers/markdown/中文 --output ./papers/merged/中文

# 3. 电池类型分类（LLM 原生支持中文）
python miner/classification/battery_type_agent.py -i papers/merged/中文 -o database/battery_type

# 4. 组件分类（按路径推断 anode/cathode/electrolyte，与语言无关）

# 5. 元数据提取 + 段落标签标注 + Chroma 入库（与英文文献同一命令）
python -m miner.meta_extraction.extract_meta database/type/Lithium_Ion_Metal_Battery -o miner/json/metadata/meta_merged.json
python miner/paragraph_metadata_pipeline_v5_qwen.py --incremental
```

**中文文献注意点**：
- 知网下载的 PDF 文件名不含 DOI（如 `2024_j_cnki_2095-4239_2024_0120.pdf`），DOI 提取脚本会将其归入 `pdf_no_doi/`；入库去重自动降级为"标题+作者"键，不影响入库
- 中文文献的 embedding（qwen3-embedding:8b）与标签标注（LLM prompt 为中文）均原生支持中文，无需改动
- 纯中文作者行（"张伟 李强 王芳"）不做正则过滤（中文姓名无可靠模式，误伤风险高），由标签标注阶段的 LLM 归入"非正文"

**分类依据**：读取 md 文件前 ~3000 字符，LLM 判断 + 关键词兜底。

## 步骤 7：段落标签标注 + Chroma 向量库入库（v5-qwen）

**这是核心入库步骤**。v5 pipeline 完成：
1. 从 `database/type/` 递归扫描 md 文件
2. 调用 `cleaner_v2_standalone` 清洗并拆分为段落
3. 对每段调用 DeepSeek LLM 打标签（6 类：电化学性能/材料属性与表征/材料制备/机理模拟/概述/非正文）
4. 标签结果写入 JSON
5. 过滤"非正文"段落（logger.info），/home/ls/xiaoyue/LLM2/LMLLM/miner/logs
6. 超长段落自动切分（双存：整段 + 子段）
7. 用 Qwen3-Embedding-8B 向量化，写入 Chroma

### 7.1 首次全量入库

```bash
python miner/paragraph_metadata_pipeline_v5_qwen.py \
  --input-root database/type \
  --output-json miner/json/Chrome/paragraph_metadata_q.json \
  --chroma-dir miner/chroma/paragraphs_q \
  --collection battery_paragraphs_q
```

**参数说明**：

| 参数 | 默认值 | 说明 |

| `--output-json` | `miner/json/Chrome/paragraph_metadata_q.json` | 标签结果 JSON |

## 步骤 8：RAG 检索问答（多智能体版）

**RAG 模块位置**：`src/lmllm/RAG/`

该模块是专为**高比能锂电池材料筛选**场景设计的多智能体 RAG 系统，采用 **Planner → Retrieval → Writer → Reviewer** 四阶段流水线。

### 8.1 架构概览

```
用户问题
  │
  ▼  Planner Agent  ─── 拆解问题为子检索问题，规划回答结构
  ▼  Retrieval Agent ─── Chroma 向量检索 + TF-IDF 混合 + Reranker 重排序
  ▼  Writer Agent   ─── 基于证据生成材料筛选对比答案
  ▼  Reviewer Agent ─── 审核数值准确性、条件完整性、幻觉删除
  │
  ▼  最终答案 + 证据段落 + 过程日志
```

**核心特点**：
- **多智能体协同**：4 个 Agent 各司其职，可独立绑定不同 LLM 模型
- **双检索后端**：Chroma 向量（默认）+ TF-IDF（fallback），支持 hybrid 混合模式
- **Qwen3-Reranker**：检索结果重排序，提升 Top-K 精度
- **多模型隔离**：Planner 用 flash（快），Writer/Reviewer 用 pro（准）
- **规则回退**：LLM 不可用时自动降级为关键词匹配 + 证据拼接
- **Prompt 审计**：所有系统 Prompt 集中在 `prompts.py`，可通过界面查阅

### 8.2 Python 编程接口

```python
from src.lmllm.RAG import RAGPipeline

# 默认：Chroma 向量检索（与入库同一数据库）
pipeline = RAGPipeline()

# 单轮问答
result = pipeline.run("NCM811和LRMO哪个能量密度更高？")
print(result["final_answer"])
print(result["evidence"])

# 导出结构化 Markdown 报告（含证据、定量数据、过程日志）
md, path = pipeline.run_with_export("固态电解质的离子电导率对比")
# 文件保存到 src/lmllm/RAG/output/

# 多轮对话（自动理解"它"指代上文材料）
result = pipeline.chat(
    "那它的循环稳定性怎么样？",
    chat_history=[("NCM811和LRMO哪个能量密度更高？", "NCM811 在 0.1C 下约 200 mAh/g...")]
)
```

### 8.5 智能体详解

| Agent | 模型推荐 | 职责 |
|---|---|---|
| **Planner** | deepseek-v4-flash | 拆解问题为子检索问题，检测标签/组件，规划回答结构 |
| **Retrieval** | — | 三阶段检索：组件过滤→标签补检索→兜底；Chroma+TF-IDF 混合融合 |
| **Writer** | deepseek-v4-pro | 只依据给定证据生成答案，标注条件，引用标记 |
| **Reviewer** | deepseek-v4-pro | 审核数值/条件/比较公平性，幻觉删除，输出置信度 |

```bash
# ===== 首次完整入库 =====

# 0. 提取 DOI，按 DOI 重命名 PDF（推荐）
python extract_doi_dedup.py        # 自带文件名去重
# 或
python doi.py                      # 带 merged 去重检查
# 或
python extract_doi_only.py         # 纯提取

# 1. PDF 转 Markdown
python preprocessing/pdf_to_markdown.py

# 2. 合并主文献 + SI
python preprocessing/merge_markdown.py

# 3. 电池类型分类
python miner/classification/battery_type_agent.py \
  -i papers/text_merged \
  -o database/battery_type

# 4. 组件分类
python miner/classification/component_type_agent.py \
  -i database/battery_type/Lithium_Ion_Metal_Battery \
  -o database/type/Lithium_Ion_Metal_Battery

# 5. 元数据提取
python -m miner.meta_extraction.extract_meta \
  database/type/Lithium_Ion_Metal_Battery \
  -o miner/json/metadata/meta_merged.json

# 6. v5-qwen 全量入库
python miner/paragraph_metadata_pipeline_v5_qwen.py

# 7. 启动 RAG（单轮 Gradio 界面，端口 7860）
python src/lmllm/RAG/single_turn/app.py

#   或启动多轮版（端口 7861，支持对话导出 + Markdown 报告）
python src/lmllm/RAG/multi_turn/app.py

#   或使用 Python 编程接口
#   from src.lmllm.RAG import RAGPipeline
#   pipeline = RAGPipeline()
#   result = pipeline.run("NCM811和LRMO哪个能量密度更高？")

# ===== 增量入库（新论文来了） =====

# 1-2. PDF 预处理（同首次）
# 3-4. 分类（同首次，新文件会被分到对应目录）
# 5. 元数据增量更新
python -m miner.meta_extraction.extract_meta \
  --incremental database/type/Lithium_Ion_Metal_Battery \
  -o miner/json/metadata/meta_merged.json

# 6. v5-qwen 增量入库
python miner/paragraph_metadata_pipeline_v5_qwen.py --incremental
```

## 关键文件说明

| 文件 | 作用 |
|---|---|
| `extract_doi_dedup.py` | **（推荐）** 从 PDF 提取 DOI，文件名重复自动跳过，支持 `--keep-larger` |
| `doi.py` | 从 PDF 提取 DOI + merged 去重检查，按 DOI 重命名 |
| `extract_doi_only.py` | 从 PDF 提取 DOI（纯提取，无去重），按 DOI 重命名 |
| `preprocessing/pdf_to_markdown.py` | PDF→Markdown（MinerU API） |
| `preprocessing/merge_markdown.py` | 合并主文献+SI |
| `miner/cleaning/cleaner_v2_standalone.py` | 文本清洗（去噪音、分段落） |
| `miner/classification/battery_type_agent.py` | 电池类型分类（4类） |
| `miner/classification/component_type_agent.py` | 组件分类（anode/cathode/electrolyte） |
| `miner/meta_extraction/extract_meta.py` | 元数据提取（标题/作者/日期/DOI） |
| `miner/paragraph_metadata_pipeline_v5_qwen.py` | **核心入库**：段落标签 + Chroma 向量化 |
| `miner/reindex_chroma.py` | 从已有 JSON 重新切分+入库（不调 LLM） |
| `src/lmllm/RAG/` | 多智能体 RAG 模块（Planner/Retrieval/Writer/Reviewer） |
| `src/lmllm/RAG/single_turn/app.py` | RAG 单轮 Gradio 界面（端口 7860） |
| `src/lmllm/RAG/multi_turn/app.py` | RAG 多轮 Gradio 界面（端口 7861，支持导出） |
| `src/lmllm/RAG/rag_pipeline.py` | Pipeline 编排器（run / chat / run_with_export） |
| `src/lmllm/RAG/agents.py` | 四大 Agent 实现 |
| `src/lmllm/RAG/config.py` | RAG 模块配置（LLM/检索/Reranker） |
| `src/lmllm/RAG/reranker.py` | Qwen3-Reranker-4B 重排序 |
| `miner/config.yaml` | 核心配置（LLM API、路径、分类参数） |
| `preprocessing/config.yaml` | PDF 预处理配置（MinerU token、路径） |
