# 材料规范标识与历史任务迁移

流程中的材料身份由 `util/material_ids.py` 统一处理，复用现有 `RelationEngine.normalize` 与材料别名表。已知名称保存为规范 ID，例如“硅碳”或“Si-C”保存为 `si_base`；原输入名保存在参数的可选 `original_value`。未知名称保持原值，不补造材料。此次不改变材料分类、别名表或 PINN 注册表的匹配范围。

需求绑定、方案参数、局部合并和检查点使用同一规则。原始课题、文献原句、材料化学式、组成、改性声明以及历史快照保持原样。参数引用可对应原句中同义名称，但来源句、证据数值和测试条件仍须通过既有校验。规范化不会解除用户锁定，也不会触发同一种材料关联参数的删除；真实换材料仍遵守原变更规则。

## 几何契约

### 从完整声明组装组件

`assemble_components(scheme, parameters)` 是审核准备、Writer 输入、适配器、局部修复及方案表提交的公共投影入口。输入仅为已验收的当前方案参数，不扫描正文或候选列表。显式 `.material` 优先；缺失时可由完整 `.nominal_formula` / `.formula` 或 `.formulation` / `.recipe` / `.composition` 建立身份。开放字段可用 `canonical_path` 明确关联这些路径。

组件字符串仍保存于 `scheme.cathode/anode/electrolyte/...`；`scheme.component_identities` 保存 `kind`、`value`、`parameter_refs` 及原字段的 `source_values`。完整组成仅做精确别名匹配，未命中保留原值，禁止因包含盐或母体名丢失配方。`flatten_scheme` 反向投影到真实来源字段，不制造无来源的 `.material`，原名义式、来源原句及用户锁定保留。重复组装/提交保持幂等。

备选、对照、文献条目、明确条件性/待定或 `complete=false` 的配方不能成为当前身份；零散盐、溶剂、浓度、掺量和母体式不能自行拼成完整配方。无法协调的完整身份声明冲突返回诊断，严格路径拒绝提交；已知材料与另一已知名义式冲突也不能静默取优先值。身份来源撤回或变更后必须重新投影，旧几何材料绑定仍需验证。

RelationEngine v2.2 将当前组成和规则母体分开：电极由明确的 `cathode.base_formula` / `anode.base_formula`（兼容 `parent_formula`、`mother_formula` 及显式 canonical_path）生成 `scheme.rule_parents`，携带当前材料值、原字段引用和原声明值。母体匹配后，掺杂名义式无需单独登记，C1–C8 按母体类别和相容性继续核对，`material_matches.basis=parent` 及 `C0_PARENT_MATCH` 审计说明边界。当前完整化学式和几何材料身份不改写，不继承母体容量、物性或 PINN 资格。

没有声明母体时仍使用原材料匹配；未知/冲突/撤回/备选母体不放行。母体变更使旧规则结果失效，母体来源和用户锁定仍须验证。C0 表示登记或识别不足，不代表实验不可行。历史产物不在只读报告渲染中自动补写身份或消除旧审核；新生成/显式重建设计使用新规则版本。

### 电解液完整配方与规则类别

v2.3将电解液原始字符串和规则类别分开。`1 mol/L LiPF6/EC+DMC`完整保留在scheme和方案表；`material_matches.electrolyte`另记录`basis=composition`、浓度/盐/溶剂/比例/添加剂/稀释剂及分类依据。EC+DMC与EC/DMC均解析为两个溶剂，未声明比例不补1:1；mol/L、M及上标写法等价，mol/kg或小写m绝不按M处理。添加剂/稀释剂需要可完整解析的正加量，未明确用途或含未解析尾部时留诊断。

分类范围来自`lmllm/RAG/data/electrolyte_families.json`，当前只覆盖1 mol/L LiPF6常规碳酸酯及表内明确添加剂；其他浓度、多盐、混合溶剂/稀释剂需要登记或扩展有依据的分类。不能仅凭浓度推断高浓或LHCE，也不能把部分解析当成完整配方。已有具体配方ID与精确别名继续可用，精确匹配仍区分M/m。材料挖掘的解析器复用同一语法，结构化输出保留完整解析结果。

分类成功只消除该配方未独立登记的C0，不证明高压稳定性、锂金属界面或性能已验证。C1–C3继续执行，明确正加量添加剂才参与原有缓解措施检查。报告说明分类口径，输入指纹涵盖分类结果；不修改用户锁定或将类别名写回完整配方。

报告渲染v22复用同一身份投影，只读展示名义组成和完整配方，摘要、第2.4节及第3.1节不再以 `.material` 是否存在判断组件缺失。类别名称与名义式并存时同时显示，不把类名替代具体组成；空单位 `null` 显示为空，不输出 `None`。这不修改方案参数、锁定、正文来源或科学审核结论。研究记录恢复仍基于当前设计正文逐字定位原句，失效原句需重新提取并审核，禁止放宽来源校验。

样品编号（如 C31）可通过当前名义式的占位引用、支持该公式的原句和支持样品编号的原句唯一关联选择理由；仍须完整通过原记录定位、参数绑定及文献校验。该关联只供第2.4节展示，不恢复 `selected_candidate_id` 或排名。研究恢复中Reviewer漏返 `reason/next_step` 等字段时最多补审核一次，仅接受匹配原指纹和漏返字段的返回，已审核状态不可覆盖；科学不支持或审核仍缺失的字段继续保留待核验。

### 明确对电极与倍率定义修复

`declared_anode_parameters` 仅从正文当前用户锁定/装配段落中的明确“对电极为 Li 金属”或“Li 金属对电极”补提 `anode.material`，保留原句及原名，规范ID为 `li_metal`。已有负极身份不覆盖，文献、风险、否定、备选不提取，也不从“半电池”名称推断材料或几何。

用户原句显式 `1 C＝250 mA/g` 可规范绑定到 `condition.C_rate_reference_current`：全角等号归一，数值字段的JSON字符串须经来源及单位联合验证再转数值；普通测试倍率、其他量纲、否定或示例不补绑定。解析失败的固定条件保留 `binding_status=pending` 及原因，不能成为无法验证的半成品契约。

`abr-cli --goal "完整既有课题" --repair-stage4-inputs` 显式修复无下游产物的Stage 4任务；只提交以上两项，不重提其他历史参数，不重跑模型、修改正文或重置修复预算。原产物存 `stage4_input_repair_history`，副本和提交后均验Stage 4门禁，不通过即保留/回滚；已有实验、仿真或报告时拒绝局部更新，须走完整下游同步。

先统一材料标识，再匹配模型及构建几何。新几何保存 `material_ids`，按两极规范 ID 校验模型基准来源。缺失的粒径与固相扩散系数可以由匹配模型补入，并保存 `model_baseline`、体系及参数版本指纹；此类方案表参数标为 `model_reference`，不表示本批材料实测。显式输入非法或越界时保留原值并拒绝推理，不能静默改用基准。

## 迁移命令

```powershell
abr-cli --goal "已有完整课题名称" --migrate-material-ids --dry-run
abr-cli --goal "已有完整课题名称" --migrate-material-ids
```

`--dry-run` 仅定位已有任务并显示迁移和阻断清单，不创建管理器、任务目录、工作流状态或运行时配置快照。正式迁移需要已有方案表和结构化几何；缺失时明确返回诊断，不从旧正文猜参数。

正式迁移在任务的 `material_migration_history/<时间>/` 保存原文件，在副本中统一当前结构化记录、补缺失基准、更新方案表和检查点身份，并核对实验绑定和报告。原文、实验步骤及所有非空设计值保留；已有审核指纹失效时摘要回退原句，不重新授予通过状态。陈旧仿真、输入和优化索引归档后失效，不运行新的推理或模型调用。原任务版本在准备或提交期间发生变化时拒绝覆盖，提交后的报告验收失败则回滚。

当前 `设计300Wh_kg高比能硅碳负极NCM811锂离子电池` 迁移后采用两极模型基准 (D_s)，仍保留负极半径 4 μm。它低于 `GrSi_NMC811` 的模型下限 4.105 μm，报告明确披露该阻断，本次不执行放电仿真。重复迁移无新增变化。
