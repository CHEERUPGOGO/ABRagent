# Stage 4流程完整性修复

本轮修复处理审核身份、局部修复权限、审核响应结构、几何恢复和候选记录接口；科学证据判断仍由Writer/Reviewer完成，程序不补科学结论。

## 1. 审核指纹与空条件

`research_support.fingerprint`将缺失、null、空字典和空数组的conditions统一为无条件。非空工况、参数值/单位/分母、原文、课题要求和引用证据仍参与完整哈希。

已有审核通过`review_fingerprint_matches`兼容有限的旧空条件表示，包括写表前Writer新字段未填conditions、旧字段已有空容器的混合情况。只比较完整指纹，不通过记录ID或相同数值认领审核。缓存逐项重验成功后可规范化指纹，原supported/unsupported/needs_review及原因原样保留。

## 2. 锁定文字的重复提及

`design_repair._protected_value_changed`允许文字声明增加提及次数，但原有出现位置须全部位于未改动文字范围内。数值保护、字段授权、来源、标题和程序引用校验保持原规则。减少/替换原材料名仍拒绝。

事务`repair_verify`收到完整原段、变更后段落和锁定参数，并明确检查新增内容是否否定、换材料或把主方案降为对照；单纯多提一次相同材料不应被视为改变参数。通过程序检查只允许进入语义复核，不能自动提交。

## 3. 完整审核对象与格式恢复

`safe_json_loads`不再跳过损坏外层、从后续内部大括号提取coverage等对象冒充完整响应。整合论证审核采用严格外层JSON解析和重复键检查，验证双指纹、coverage、每段和每项limitation的唯一ID、状态与理由，以及issues数组。

字符串外唯一缺失的内部闭括号可确定性补一个字符，恢复后仍须完整结构校验；原始响应、位置及哈希进入protocol_record。截断、缺字段、指纹不匹配等不能因此放行。

纯审核协议失败使用原有两次审核总预算中的剩余机会，重审同一已通过绑定校验的论证稿，不调用生成器重写。科学否决仍走原内容修复路径。请求前保存次数/phase，中断不自动重发，耗尽不重置。

## 4. 声明驱动的几何恢复

`geometry_from_declared_parameters`先核对主工况、数值、单位与一致性，再用已有厚度、孔隙率、半径和条件构建契约。已有非法几何、同字段冲突或材料身份失效不能被恢复覆盖；未声明的厚度/孔隙率拒绝。明确D_s仍须同材料、温度和适用性的原文证据；模型基准须符合当前材料注册信息，锁定null不得回填。

该路径接在检查点恢复与适配器中，不新增几何模型调用、不重置原修复/审核预算。无匹配模型时缺失D_s保持null；缺项、非主工况或证据不满足仍明确报告错误。

## 5. 候选材料名与展示角色

候选name表示原文材料/样品名称，candidate_role可选主推候选、备选候选、对照组或文献参照，display_name保存展示组合。兼容旧模型将角色附在name后面的写法，但材料名和角色须在同一条已定位source_quotes出现，scope必须一致，不跨不同候选拼接。

角色不授予首选资格：selected_candidate_id仍须完整引用当前主方案身份，并经过科学支持性审核。名称不存在、角色夸大或来源失效继续拒绝。

## 验证

本次真实课题档案只读回放：17条审核身份恢复匹配；首次7个修复事务均能进入后续语义复核；声明几何通过验证且两极D_s保持null；Zn–Na、Cu–Na候选身份与角色分离后通过来源校验；首版整合审核恢复完整8段。原课题文件哈希未变，未重跑模型或发布新报告。

测试覆盖真实输入变化导致旧审核失效、科学否决不被提升、锁定材料不能更换、内层JSON不能冒充外层、格式重试不重生成、恢复不重置预算、几何缺项/单位/工况/证据拦截，以及候选来源/身份/角色分离。
