# Stage 5与主方案的一致性

主方案已确定且适用于本轮实验的内容，Stage 5继承并按相同用途执行。新增操作细节可以是工程建议，不能覆盖当前材料、配方、工况或主备选身份。

## 当前实现

- 由当前方案表及有效结构化方案建立执行条件，分为制备、装配、测试、判据。程序补齐引用并在第五部分展示未被正文重复的继承条件，避免“模型没写就丢失”。
- 常规循环、高压应力、化成各自提供工况引用。`{{profile:main_cycle}}`等标记只展开已声明的字段，不推断缺项；步骤与目标表共用。普通参数引用仍兼容，但明确跨工况错配会定位到原条目。
- 明确等价单位及同义字段允许通过；单位、条件、分母不能因数值相同而混同。已声明设计值仍可标待实测，不能写成尚未定案。
- 完整JSON初稿及原有一次结构修复之后，单独核对主方案与实验文字的一致性。只处理有依据的矛盾，不因没有完成科研验证、文献不足或后续优化缺项否决。最多两次核对和一次受限文字补丁，调用与原响应持久留档。
- 同步参数绑定后旧语义审核按实际输入失效，不继承过时通过状态。重复读取同一输入不重发模型请求，也不重写未变化缓存。
- 旧载量诊断只有在主工况的总面载量、活性面载量、厚度和压实密度重新核对一致后结案。原审核意见保留，结案另存依赖声明及计算结果；声明变化后结案不再生效。

## 既有课题

```powershell
abr-cli --goal "原课题目标" --sync-experiment-plan
```

维护在课题`experiment_alignment_recovery_history`保留原文件、调用、修订稿和审核结果。仅同步实验及相关交付状态，保留主方案、用户锁定、研究论证和原科学意见；副本Stage 4/5/6验收后发布，发生外部修改或验收失败保留原报告。不以撤下原有效步骤代替本次一致性修复。

实验交付与性能验证分开：已给出当前推荐、仅最优性或效果待实验确认的目标，可用`gap_kind=validation`和`recommendation_refs`保留验证边界，不单独触发CONDITIONAL。留空且未被本轮操作或判据使用的电极扩散系数也只作待测说明。未给推荐、缺必要执行条件、当前参数冲突和必需物理验证失败仍阻断。执行器、Checker、恢复与报告共用`experiment_delivery.py`判定；旧目标状态不会在只读检查时静默改写，科学审核不因此提升。
